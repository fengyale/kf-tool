# DocToolkit

中文公文排版 + 图片 / PDF 转文字，一组可独立使用的命令行小工具。

| 工具 | 干什么 | 入口 |
|---|---|---|
| **公文排版** | 把写好的文字排成规范 Word（A4、宋体小四、1.5 倍行距、标准页边距、页码、版权与版本号） | `gongwen.bat` / `gongwen.py` |
| **图片 / PDF 转文字** | 把扫描件、截图、有文字层的 PDF 变成 Word 初稿 | `ocr2docx.bat` / `ocr2docx.py` |
| **加版权** | 给**已有的** Word 文档补上版权归属、版本号和页码，正文一个字不动 | `add_copyright.bat` / `add_copyright.py` |

Windows 上三个都支持**拖拽**：把 txt、图片文件夹、PDF 或 docx 直接拖到对应的 `.bat` 上即可，不用敲命令。

---

## 安装

需要 Python 3.9 或更高版本。

```bash
pip install -r requirements.txt
```

依赖说明：

| 包 | 用途 |
|---|---|
| `python-docx` | 生成 / 修改 .docx |
| `numpy`、`Pillow` | 图像处理 |
| `rapidocr-onnxruntime` | 中文 OCR 引擎（自带模型，会连带装 opencv / onnxruntime / shapely） |
| `pymupdf` | PDF 文字层抽取 + 图像版渲染 |

**注意 `pymupdf` 是 AGPL-3.0 或 Artifex 商业双许可**，本项目因此整体采用 AGPL-3.0，详见文末「许可证」。

> 仓库里不含 `vendor/`。如果你在离线环境，可以用 `pip install --target vendor/libs -r requirements.txt`
> 预先装到本地目录，脚本会自动优先从 `vendor/libs` 加载（见 `ocr2docx.py` 顶部）。

## 一、公文排版 `gongwen`

### 最快用法

1. 用记事本（或任何编辑器）把正文写成 `.txt`，**存为 UTF-8 编码**
2. 把 `正文.txt` 拖到 `gongwen.bat` 上
3. 同目录出现 `正文.docx`，打开即可

### 命令行用法

```
gongwen.bat 正文.txt                        → 正文.docx
gongwen.bat 正文.txt -o 通知.docx
gongwen.bat 正文.txt --title "关于XX的通知" --subtitle "（试行）"
gongwen.bat 正文.txt --font-size 14 --line-spacing 1.75
gongwen.bat 正文.txt --no-page-number       → 不显示页码
gongwen.bat 正文.txt --no-indent            → 正文不首行缩进
gongwen.bat 正文.txt --owner "某某公司" --version "V2.0"   → 加上版权归属方与版本号
gongwen.bat --help                          → 全部参数
```

### 标记写法

**大部分情况什么都不用标**——工具按中文序号自动判断层级：

```
某某公司员工行为规范管理制度                ← 首行自动作标题
（试行）                                    ← 需要副标题就写 --subtitle，或下面用 %S
一、目的                                    ← 自动识别为一级标题
为规范员工职业行为……制定本制度。            ← 自动识别为正文
（一）基本定义                              ← 自动识别为二级标题
1、公司                                     ← 自动识别为三级标题
```

需要精确控制时用显式标记：

| 标记 | 作用 |
|---|---|
| `%T 文字` | 文档大标题 |
| `%S 文字` | 副标题（如「（试行）」） |
| `# 文字` | 一级标题 |
| `## 文字` | 二级标题 |
| `### 文字` | 三级标题 |
| `%C 文字` | 居中段落 |
| `%R 文字` | 右对齐（落款、日期） |
| `%P 文字` | 强制当正文，不做标题识别 |
| `%PAGE` | 分页符（也可写 `---`） |
| `\| 列1 \| 列2 \|` | 表格行，连续多行组成一张表，首行为表头 |

表格示例：

```
| 序号 | 单位全称 | 是否适用 |
|---|---|---|
| 1 | 某某科技有限公司 | 是 |
| 2 | 某某信息技术有限公司 | 是 |
```

列宽按各列内容长短自动分配，总宽严格等于版心宽度，不会顶到页边距外面。

### 版权与版本号（默认关闭）

工具支持在页脚和文末生成版权声明，**但默认不生成**——开源工具不该往别人的文档里塞自己的名字。需要时显式指定：

```bash
gongwen.bat 正文.txt --owner "某某公司" --version "V1.0"
```

效果：

| 位置 | 内容 |
|---|---|
| **页脚**（每页） | `版权所有 © 某某公司　版本号：V1.0　第 X 页` |
| **文末** | 一条细横线 + `本文件内容版权归 某某公司 所有，未经书面许可，不得复制、转载或用于商业用途。　版本号：V1.0` |

开关组合：

```bash
gongwen.bat 正文.txt --owner "某某公司"          # 只要归属方，版本号沿用默认
gongwen.bat 正文.txt --version "V2.3-2026"       # 单独指定版本号
gongwen.bat 正文.txt --owner "某某公司" --no-copyright-note   # 只要页脚，不要文末声明
gongwen.bat 正文.txt --no-copyright              # 整个不要
```

默认版本号是 `V1.0`，定义在 `gongwen.py` 顶部；归属方默认为空：

```python
DEFAULT_OWNER = ""
DEFAULT_VERSION = "V1.0"
```

`ocr2docx` 也有同样的参数（`--owner` / `--version` / `--no-copyright`），所以识别出来的初稿也能直接带版权。

页脚里的页码是 Word 域，打印和转 PDF 会自动更新，不用手动改。

### 版式规格（`gongwen.py` 顶部常量，可按需改）

- 纸张 A4 210×297mm，页边距 上 3.0 / 下 2.5 / 左 2.8 / 右 2.6 cm
- 正文 宋体 小四(12pt)、1.5 倍行距、首行缩进 2 字符、两端对齐
- 标题 黑体 18pt，副标题 黑体 16pt，一级标题 黑体 14pt，二三级标题黑体/宋体加粗 12pt
- 页脚居中页码，前面带「版权所有 © 归属方　版本号：xxx」
- 页脚行距设成单倍、字号 9pt，不会把正文挤出版心
- 中文字体用 `w:eastAsia` 显式指定——不指定的话 Word 会显示成宋体但实际渲染成等线

## 二、图片 / PDF 转文字 `ocr2docx`

### 用法

```
ocr2docx.bat 图片目录                        → 初稿.docx
ocr2docx.bat 通知.pdf -o 制度初稿.docx
ocr2docx.bat 1.png 2.png 3.png -o 初稿.docx
ocr2docx.bat 图片目录 --title "关于XX的通知"
ocr2docx.bat 图片目录 --passes 1              → 只跑一遍（最快，精度略降）
ocr2docx.bat 图片目录 --passes 3              → 三遍识别（最准，慢约 40%）
ocr2docx.bat 图片目录 --max-recheck 0         → 完全不做裁切复识（最快）
ocr2docx.bat 图片目录 --no-tables             → 不做表格检测
ocr2docx.bat 图片目录 --no-docx               → 只出 txt 和报告
ocr2docx.bat 图片目录 --recheck-below 0.92    → 更严格地复识（更慢）
```

图片按文件名中的数字排序（`1.png`、`2.png`……`10.png` 顺序正确）。支持 png / jpg / bmp / tif / webp，以及 PDF。

速度参考（普通办公电脑、19 页 A4 扫描件）：`--passes 2`（默认）约 12–13 分钟，单页约 40 秒。`--passes 1 --max-recheck 0` 可压到 3 分钟左右。

### PDF 是**两种东西**，工具会自动分开处理

实际工作里叫「PDF」的文件其实分两类，处理方式完全不同：

| 类型 | 怎么认 | 工具怎么做 | 速度 |
|---|---|---|---|
| **文字版 PDF**（Word/WPS 直接导出的） | 有文字层，能选中、能复制 | **直接抽取文字**，完全不跑 OCR | 秒级 |
| **图片版 PDF**（扫描件套了个 pdf 后缀） | 整页就是一张大图，选不中文字 | 渲染成图，走 OCR | 与图片同速 |

判定是逐页做的（一个 PDF 里混着两种页也能处理）：页面可提取字符 ≥80 且不是「大图 + 极少文字」，就当文字页；否则当图片页。运行时会打印每页走的是哪条路：

```
共 21 页待处理（其中 21 页有文字层，直接抽取；0 页走识别）
  抽取 1/21  test.pdf#p1  (PDF 文字层)
```

文字版 PDF 额外做了两件必要的事：

1. **去自动间距**：Word 导出 PDF 会在汉字与数字/字母/全角标点之间插间距，抽出来是「5 个工作日」「OA 系统 发起」。工具把空格任一侧为中文/全角标点的空格删掉，两侧都是英文数字的保留（`Windows 10` 不会被粘连）
2. **表格按单元格重建**：PDF 库自带的表格抽取会把单元格里被折行的内容拆成 `口头表扬 / 、 / 书面表扬` 这种碎片。工具改为取文字块坐标、按行聚、行内按 x 排序再拼，得到 `口头表扬、书面表扬`

图片版 PDF 额外做一件事：**按原生分辨率渲染**。工具读页面里那张图的原始像素数，反推它本来就是多少 dpi（150dpi 的扫描件就按 150dpi 渲染），再按这个 dpi 渲染成位图。固定 200dpi 会把图放大 1.33 倍，字符间隙变大，OCR 就会多识别出一堆空格。

### 产出三个文件

| 文件 | 用途 |
|---|---|
| `初稿.docx` | 排好版的 Word 初稿 |
| `初稿.txt` | 同样内容的纯文本。**建议在这个文件上改**，改完用 `gongwen.bat 初稿.txt` 重排，比在 Word 里调格式省事 |
| `初稿.report.txt` | 每页行数、哪些行被复识修正过、哪些行仍然存疑（后者务必人工核对）、表格检测情况 |

### 它是怎么工作的

1. **多遍识别**：默认原尺寸、放大 2 倍各识别一次（`--passes 3` 再加一遍 2.5 倍+锐化），同一行取置信度最高的结果。跨尺度的坐标会先归一化回原图，否则行会错并成乱码
2. **裁切复识**：置信度低于阈值（默认 0.86）或两遍结果不一致且置信度低于 0.95 的行，按该行坐标裁出横条、放大 2/3/4/6 倍再识别，置信度达标即提前停止。每页最多复识 8 行（`--max-recheck`）
3. **补漏行**：多遍识别和复识都发现不了「整行被吞」——那一行根本没有文字框。工具用**纵向行距异常**检测：正常行距约等于行高，相邻两行之间空出一个行高以上就裁开重认，用 4/6/8 倍三档取识别框最多的那遍
4. **段落合并**：按行首缩进判断段首，把行拼成段落；跨页处上一页末段没写完的会与下一页首段拼回一段（拼完再过一遍错字表——「纪律资|任」这种断字只有拼起来才认得出）
5. **序号修正**：把漂到行尾的孤立序号搬回下一行开头；连续列表项编号错乱时按出现顺序重编；圈号 ①②③ 同理
6. **层级推断**：按「一、」「（一）」「1、」规则判断标题级别
7. **表格还原**：检测页面上的长直线网格，有网格就逐单元格按 y 聚行、行内按 x 排序识别；表格与正文共存时会按 y 坐标切开，正文不会丢
8. **错字修正**：内置约 120 条形近字词组表。表里只放「几乎不会出现在正确文本里」的词组（如 资任→责任、整告→警告、篇要→需要），**不放单字替换**——单字会改坏正确文本
9. **标点规范化**：中文语境里的半角 `(),;:!?` 转全角，但英文、数字、版本号（`5.0`、`1:2`、`A/B`）保持原样

### 精度实测

拿一份人工逐字校对过的 19 页制度文档做基准对比（用仓库里的 `cmp_docx.py`，标点归一化后按字符比对）：

| 输入 | 字符级一致率 | 差异片段 | 耗时 |
|---|---|---|---|
| 19 张 PNG，最初版本 | 95.76% | 84 处 | — |
| 19 张 PNG，修完结构缺陷 | 99.58% | 59 处 | — |
| 19 张 PNG，最终版本 | **99.92%** | 11 处 | 约 13 分钟 |
| **同一文档的文字版 PDF** | **99.97%** | 2 处 | **秒级** |
| **同一文档的图片版 PDF**（扫描件套 pdf 后缀） | **100.00%** | 0 处 | 与图片同速 |

图片 OCR 剩下的 11 处：7 处是 OCR 把 `；` 或 `，` 认成 `：`（中文里字形接近，规则上无法可靠区分），1 处丢了一个圈号 `⑥`，1 处多一个空格，2 处是附件标题后的双空格被吞。全部属于「人工扫一眼就能改」的级别，没有丢段、没有错词。

文字版 PDF 剩下的 2 处就是那两个附件标题后的空格（PDF 里本来就是两个空格排的版，抽取时被合并成一个）。

**图片版 PDF 走的是和图片完全相同的识别流程，只是多了一步「把 PDF 渲染成位图」。**
实测过 4 页（正文首页 + 最难识别的「工时浪费」段 + 两张附件表），结果与直接把同样 4 张 PNG 喂进去**逐字符 100% 一致**。

**结论：能拿到文字版 PDF 就别用图片。** 精度更高、速度快几十倍。

### 必须知道的限制

**这是初稿，不是成品。** 具体说：

- **形近字会错**（图片 OCR 路线），而且这类错置信度往往很高，多遍识别和复识都纠正不了。工具内置约 120 条常用错字表，但覆盖不全，新文档会有新错字
- **标题层级靠规则猜**，遇到不规范的序号会判断错
- **表格靠网格线检测**（图片路线），无框线的表、合并单元格、跨页表都会失败，需要手工重建
- **扫描倾斜、印章压字、手写批注**基本无法处理
- 页码会被自动剔除（靠「位于页底 8% 且水平居中且形如数字」三条同时成立）
- 文字版 PDF 如果本身是扫描件加了隐藏文字层（OCR 过的 PDF），抽出来的文字质量取决于当初那次 OCR，本工具不会再识别一遍

所以流程应该是：**跑出初稿 → 看 `初稿.report.txt` 里标注的存疑行 → 在 `初稿.txt` 上通读改正 → 用 `gongwen` 重排**。这样比从零打字能省 70–80% 的时间。

### 配套工具 `cmp_docx`

评估自己改得准不准、或比较两个版本的差异时用：

```
python cmp_docx.py 基准.docx 待比对.docx -o 报告.txt
```

输出字符级一致率、差异片段数量，以及每个差异片段的上下文（前后各约 20 字）。标点做了归一化（`,`/`，`、`;`/`；` 等视为相同），只比实质内容。读 docx 时表格会按 `| 列1 | 列2 |` 拼进正文一起比。

## 三、给已有 Word 文档加版权 `add_copyright`

这份文档是别人排好的（不是用 `gongwen` 生成的），但你同样想给它加上版权和版本号——用这个：

```
add_copyright.bat 文档.docx                          → 原地覆盖，加上版权
add_copyright.bat 文档.docx -o 新文档.docx             → 另存一份
add_copyright.bat 文档.docx --owner "某某公司" --version "V2.0"
add_copyright.bat 文档.docx --no-copyright-note        → 只要页脚，不要文末声明
add_copyright.bat 文档.docx --no-copyright             → 整个不要（页脚只留页码）
```

和 `gongwen` 用的是同一套页脚构造逻辑：

```
版权所有 © 某某公司　版本号：V2.0　第 X 页
```

**正文、表格、段落格式一个都不动**，只在页脚加东西、在文末追加两行（一条细横线 + 一行声明）。

验证过：给一份 21 页的成品文档加版权后，正文与加之前的字符级一致率 **100.00%**，页数不变，页脚在导出的 PDF 里每页都在。

## 五、故障排查

**`gongwen` 报「找不到模块 docx」**
没装依赖。执行 `pip install -r requirements.txt`。

**`ocr2docx` 报「找不到模块 rapidocr_onnxruntime」**
同上，没装依赖；或者你用了离线 `vendor/libs` 但目录路径不对。

**文字版 PDF 被当成图片走了 OCR（很慢）**
说明这页判断错了。判定阈值是「可提取字符 ≥80」。如果某页文字很少（如只有一行的封面、纯章标题页），会被当图片页。这通常不影响结果，只是慢一点；必要时可把那几页单独处理。

**图片版 PDF 抽出满页乱码**
说明这页其实有「假文字层」（扫描件 + 很烂的隐藏 OCR 层）。可拆成图片再跑，强制走 OCR 路线。

**输出的 Word 里中文是等线/宋体不对**
工具已显式设 `w:eastAsia`。若仍异常，可能是 Word 版本对 `w:rFonts` 的处理差异，检查「开始→字体」里是否被套用了其他样式。

**表格超出页边距**
`gongwen` 的 `fix_table()` 已强制固定布局。若自己改过列宽导致超宽，检查传入的 `widths_cm` 总和是否小于版心宽度（21 − 2.8 − 2.6 = 15.6 cm）。

**bat 窗口里中文乱码**
bat 里已设 `chcp 936` 和 `PYTHONIOENCODING=gbk`。若在非中文系统（例如英文 Windows）下仍是乱码，可把 `chcp 936` 改成 `chcp 65001` 并把 `PYTHONIOENCODING` 设为 `utf-8`。

**在 Linux / macOS 上用**
`.bat` 是 Windows 专用，其它平台直接调用 Python：

```bash
python gongwen.py 正文.txt
python ocr2docx.py 图片目录
```

选择 AGPL 的原因：核心依赖 **PyMuPDF 采用 AGPL-3.0 / Artifex 商业双授权**。AGPL 的传染性要求：分发本软件时，整个组合作品须以 AGPL 发布。因此本项目不能使用 MIT / Apache-2.0 之类的宽松许可。

这意味着：

- ✅ 你可以自由使用、修改、再分发，包括商用
- ✅ 修改后的版本也必须以 AGPL 开源
- ⚠️ 如果你把它做成网络服务供他人使用，需要向使用者提供对应源码（AGPL 第 13 条）
- ⚠️ 如果你需要在闭源产品里使用，需要去掉 PyMuPDF 依赖，或从 Artifex 购买商业授权

如果你只需要 `add_copyright.py`（仅依赖 `python-docx`，MIT），它是整个项目里唯一不碰 PyMuPDF 的部分，可以单独按 MIT 使用。
